# 系统-自动触发-ID设计节点触发

### 业务规则

当研发项目立项、手板样节点开始、研发项目废弃或 ID 设计需求完成时，系统自动更新「ID设计需求」及相关节点记录。

触发条件：
研发项目立项通过后，生成或初始化「ID设计需求」
手板样节点开始且「ID设计需求」处于「已确认」时，触发进入「待更新」
研发项目被废弃且已存在「ID设计需求」时，触发状态变更为「已废弃」
「ID设计需求」状态变更为「已完成」时，触发记录项目设计完成节点

取值逻辑：
【需求创建时间】取研发需求审批通过即立项时间
【预计初版方案完成时间】按【需求创建时间】加参数配置时间计算
【预计完整方案完成时间】按【需求创建时间】加业务配置时间计算
【预计更新时间】有手板时取手板样预计认证时间，无手板时为空
【状态】立项后默认为「待提交」

### 异常场景

已存在ID设计需求：不重复生成，仅按触发事件更新对应字段
无手板：不触发「待更新」，确认方案后可进入「已完成」
研发项目已废弃：不允许继续提交、确认或更新方案
重复触发完成节点：同一 ID 设计需求完成节点只记录一次

### 通过校验后执行

执行1：生成或更新「ID设计需求」
执行2：按触发条件更新状态和日期字段
执行3：当状态变更为「已完成」时，记录项目的设计完成节点
执行4：记录系统触发日志

### 不在范围内

不支持手工修改系统自动计算的预计时间
