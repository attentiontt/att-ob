
### 1.需求背景
4月份在梳理呆滞采购订单的时候，发现很多呆滞订单与产品退市有关，因此邀请开发、运营、备货和采购就产品退市流程开展workshop讨论。大家讨论并收集了当前退市流程的痛点并组决策搭建一个退市面板，涵盖产品退市全流程，确保信息透明，状态清晰

7.痛点表

待确定清单
运营如何确定要退市，需要和谁确认，需要由谁审批


| 问题节点     | 问题清单                                           |                                    |
| -------- | ---------------------------------------------- | ---------------------------------- |
| 确定退市     | 这里的退市具体指什么？是停止销售、停止补货、平台下架，还是系统里标记生命周期结        | 系统标记完结                             |
| 确定退市     | 退市的判断对象是什么？是 SKU、SPU、店铺 SKU，还是某个平台链接？          | 店铺sku<br>amazon：asin<br>temu：规格i型号 |
| 确定退市     | 运营确定退市前需要看哪些数据？这些数据是系统自动取，还是人工判断？              |                                    |
| 确定退市     | 什么情况下会触发退市？有没有固定指标，比如销量、毛利、库存周转、退货率、差评率、广告亏损等？ |                                    |
| 确定退市     | 运营员是直接决定退市，什么时候决定退市，还是只是发起退市申请？有没有审批人          |                                    |
| 确定退市     | 确定退市后，运营需要产出什么？比如退市 SKU 清单                     |                                    |
| 通知计划     | 通知什么、通过什么方式、通知后计划要做什么                          |                                    |
| 登记呆滞订单表  | 登记哪些数据、来源是什么、谁维护                               |                                    |
| 录入销售亏损   | 销售亏损怎么算、谁提供数据、是否审批                             |                                    |
| 录入预计计损   | 预计计损依据是什么、采购怎么确认                               |                                    |
| 整合所有信息   | 整合哪些信息、缺失怎么办、输出什么                              |                                    |
| 提交发货方案   | 发货方案包括什么、谁审核、和库存处理关系                           |                                    |
| 提交库存处理方案 | 处理方式有哪些、谁拍板、是否影响财务                             |                                    |
| 库存处理     | 谁执行、怎么反馈结果、异常怎么闭环                              |                                    |
