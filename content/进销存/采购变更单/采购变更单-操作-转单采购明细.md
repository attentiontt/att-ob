# 采购变更单-操作-转单采购明细

### 业务规则

入口：从「新建/编辑采购变更单」明细行点击「转单」。
展示逻辑：只有原本存在的采购单明细才展示「转单」按钮。
展示逻辑：点击「转单」后弹出「转单」窗口，选择同 Modelnumber 下可承接转单的商品明细并填写【转单数量】。

转单候选筛选
【只看下单状态为下单的数据】勾选项，默认待确认
当勾选【只看下单状态为下单的数据】时，系统查询同 Modelnumber 下所有在售 goods ID，且 goods ID 关联的运营分级存在「已下单」数据；如果全部运营分级都是「不下单」，不展示
当未勾选【只看下单状态为下单的数据】时，系统查询同 Modelnumber 下所有在售 goods ID
候选商品必须存在启用的供货关系

转单明细
【图片】展示
【产品名称/SKU】展示
【Msku/条码】展示
【销售平台】展示
【发货国】展示
【店铺】展示
【品牌】展示
【装箱数】展示
【转单数量】数值输入框，默认0，必填
【汇总】展示本次转单数量合计，示例「汇总：300」

### 点击确定时校验

校验1：前端校验【转单数量】汇总是否大于可转单量；不满足提示：转单量汇总无法大于可转单量。
校验2：前端校验【转单数量】汇总是否为0；不满足提示：转单量需要大于0。
校验3：前端校验【转单数量】汇总是否为原 goods ID 装箱数的倍数；不满足提示：转单量汇总需要符合{Msku/销售平台/发货国/店铺}的整箱数。
校验4：前端校验每条【转单数量】是否为新 goods ID 装箱数的倍数；不满足提示：转单量需要符合{Msku/销售平台/发货国/店铺}的整箱数。
校验5：后端校验原采购明细【剩余订单量】是否发生变化；已变化时提示：序号为{序号}的msku/销售平台/发货国/店铺的剩余订单量已变更，请刷新当前页面重试。
校验6：后端校验当前用户是否有编辑采购变更单权限；不满足提示：无权限操作。

### 通过校验后执行

执行1：关闭「转单」窗口。
执行2：按 goods ID 将转单商品增加至采购变更单明细。
执行3：新增转单明细展示「转单」标签。
执行4：原始采购单明细【待转单量】增加本次转单量。
执行5：新增转单明细【采购量】取本次转单数量。
执行6：新增转单明细允许修改【总含税金额】。

### 移除转单明细

入口：从「新建/编辑采购变更单」转单生成的明细行点击「移除」。
展示逻辑：只有转单生成的采购变更明细才可以操作「移除」。
执行1：移除当前转单明细。
执行2：原始采购单明细【待转单量】按被移除明细的转单量对应减少。
执行3：重新计算采购变更单明细汇总金额。

### 异常场景

候选 goods ID 不存在启用供货关系：不展示为可转单候选。
全部运营分级都是「不下单」且勾选只看已下单：不展示为可转单候选。
原型中「转单量>0且<-剩余订单量」疑似为「转单量>0且<=剩余订单量」，比较符号待确认。

### 不在范围内

不在本模块定义商品、运营分级、供货关系的维护规则。
